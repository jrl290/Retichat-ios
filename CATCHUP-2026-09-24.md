# Bringing Retichat-ios up to the 2026-09-24 contract

Instructions for the session that does this work. Read
`DESIGN_PRINCIPLES.md` and `CHECK_THESE_THINGS_FIRST.md` (§14 is today's) in
the workspace root first. Everything below was decided and shipped for the
web client (Retichat-js 1777b8c) and Android (Retichat-android e81ddb7 and
later) on 2026-09-24; iOS has not been touched since.

## What iOS gets for free by rebuilding the framework

The iOS FFI crate is `Retichat-ios/rust/retichat-ffi` with path deps on
`../../../Reticulum-rust` and `../../../LXMF-rust`. Rebuild with
`cd Retichat-ios && ./build_rust.sh release` (cross-compiles device,
simulator, Catalyst; copies the xcframework into `Retichat/`). The header
`Retichat/Bridge/CRetichatFFI.h` is **hand-maintained** — `build_rust.sh`
only copies it — so every new export needs a declaration added by hand.

Rebuilding at Reticulum-rust ≥ 8079930, LXMF-rust ≥ b8327f5, app-links ≥
e6840a7 brings, with no Swift change:

- **Distro announce flag.** `retichat_distro_announce_payload` calls
  `lxmf_rust::distro::announce_payload`, which now always writes app_data
  `[nil, nil, [0xD0]]` (`SF_RFED_DISTRO`, RFed SPEC §17.10). iOS passes
  `nil` app_data today (`RfedDistroClient.announcePayload`), which is right.
- **Identity transfer parsing.** `retichat_distro_unwrap` now recognises a
  transfer only as `FIELD_CUSTOM_TYPE (0xFB) == "rfed.distro.transfer"` with
  the key in `FIELD_CUSTOM_DATA (0xFC)` (SPEC §17.9). The JSON field
  `distro_transfer_key` that `RfedDistroClient` reads is unchanged. Field
  `0x0D` is never read any more (it is LXMF 1.1.1's `FIELD_EVENT`).
- **Propagated sends are SENT only when the node proves them** (LXMF-rust
  b8327f5). A message handed to the propagation link stays SENDING until the
  proof; a receipt timeout returns it to OUTBOUND and tears the link down.
  Check any Swift code that treated state 4 as "queued" and any UI mapping.
- **Stack shutdown closes every app-link and runtime link.**
  `lxmf_client_shutdown` → `LxmfClient::shutdown` → `AppLinks::close_all()`
  then `reticulum_rust::ffi::shutdown()` (runtime links torn down). Until now
  a stop/start inside one process inherited dead links that reported
  ACTIVE. Re-test `ChatRepository` stop/start and the NSE hand-off.
- **`retichat_packet_send_to_hash` returns non-zero when nothing was sent.**
  `reticulum_rust::ffi::packet_send` used to return 0 both for "sent, no
  receipt" and "no interface took it". `RetichatBridge.packetSendToHash`
  has **no callers** in the app (checked 2026-09-24), so nothing changes
  today; any future caller gets an honest result.
- **Transport:** tunnels restore paths across reconnects/restarts (B32),
  pacer-queued own announces count as sent, six-hour announce cadence (B28),
  route eviction (B29), bind retry (B30). No Swift impact beyond timing.

## Swift work that is required

0. **Wire the distro feature at all — it is dead code today.**
   `Services/DistroManager.swift` and `Services/RfedDistroClient.swift`
   are compiled (the project uses synchronized folders) but nothing calls
   them: no screen, no `register` on stack start, no routing of
   `rfed.delivery` blobs whose 16-byte prefix is the distro address into
   `RfedDistroClient.handleBlob` (`RfedChannelClient.onRfedBlob` treats
   every prefix as a channel), no consumer of `onIdentityOffered`, and
   outgoing messages never sign as the distro. iOS cannot hold a distro
   yet. Mirror Android: load the key at stack start, register + hand over
   the pre-signed announce after the rfed link is up, pull on start and on
   wake, route distro-prefixed blobs in `onRfedBlob`, send as the distro
   when one is loaded (Android `DistroManager.sendingIdentity`), and show
   the transfer offer. Items 1–7 below assume this is done.
1. **Expose the distro flag.** Add to `rust/retichat-ffi/src/lib.rs`:
   `retichat_peer_is_distro(dest_hash, len) -> u8` returning
   `lxmf_rust::ffi::peer_is_distro(...)` (reads the destination's last
   announce; unknown destinations are not distros). Declare it in
   `CRetichatFFI.h`, wrap it in `RetichatBridge.swift`.
2. **Send path: a distro contact propagates at once.** Mirror Android
   `ChatRepository.sendDirectMessage`: before the DIRECT attempt, if
   `peerIsDistro(dest)` (or a stored per-contact flag) is true, skip the
   direct link and dispatch the PROPAGATED copy immediately. LXMF-rust's
   `handle_outbound` also switches `desired_method` to PROPAGATED when the
   announce is already known, so the router side is covered — verified on
   2026-09-24: the simulator's Swift layer chose DIRECT, the rebuilt router
   logged "is a distro address (announce) — sending PROPAGATED", the node
   proved it and the bubble showed SENT. The Swift check only matters for
   the UI's initial method and for addresses whose announce is not yet
   heard.
3. **Remember the flag from announces.** Where iOS handles delivery
   announces (the announce callback that feeds contact names), call
   `peerIsDistro` and store it per contact, as Android's
   `ChatRepository.onAnnounceReceived` does. Do it before any early return on
   an empty display name — a distro announce has no name.
4. **`lxma://hash:pubkey` is not a distro indicator.** iOS never marked
   distros from the link (it has no `isDistro`), so nothing to remove; keep
   `IdentityShareFormat` remembering the public key
   (`retichat_identity_remember_lxmf_delivery`). Do not add a link-based
   heuristic.
5. **Identity transfer, send side (optional, parity with Android/web).**
   Nothing on iOS sends or surfaces transfers today (see item 0). To offer a distro
   to another device, build an LXMF message signed as the *device* (not the
   distro) with fields `0xFB = "rfed.distro.transfer"` and `0xFC = <128
   hex>`, title "Distro Identity", sent DIRECT then PROPAGATED. Check whether
   the iOS LXMF message API can set arbitrary fields; Android uses
   `messageAddFieldString(handle, 0xFB, ...)`. Add a "Add another device"
   action on the Identity screen like Android's.
6. **Identity screen parity.** Android's `IdentityScreen` shows the distro
   address, its `lxma://` contact link, generate/import/forget and the
   transfer offer dialog; iOS has none of it (item 0). Match the wording
   used on Android and the web.
7. **Key safety.** `DistroManager.importKey` on Android now backs up a
   different existing key to `distro_identity.bak-<hash8>-<ts>` before
   replacing it. Do the same wherever iOS writes the distro key (Keychain
   item): write the previous item under a dated key first.

## rfed.link

The web client moved every RFed operation onto the single `rfed.link`
destination (RFed SPEC §"rfed.link — one destination for all of it": same
payloads, addressed by request path, e.g. `/distro/register`,
`/channel/subscribe`, `/propagation/stream/open`; node→client pushes
`/delivery`, `/lxmf/delivery`, `/notify` come back over the same link).
iOS and Android still use the per-destination paths
(`rfed.distro.register` + `/rfed/distro/register`, etc.). rfed serves both
and the spec calls `rfed.link` additive, so **no iOS change is required to
work**. Migrating is a consistency task: one link per node instead of one
per operation, and the push-back model replaces the separate stream
destinations. Do it after items 1–3, together with Android, and verify on
staging with `probe_phone_holds_distro.mjs` style runs.

## Verified on 2026-09-24 (framework rebuilt, no Swift changes)

Simulator "Retichat-Test" (iOS 26.5), app set to LAN-only (192.168.2.1 +
AutoInterface), production rfed:

- Only TCP peer was 192.168.2.1; rfed paths READY via the gateway; rfed
  notify registration delivered; public.general re-subscribed.
- Simulator → a phone-held distro with the 0xD0 flag: PROPAGATED at once,
  proved → SENT, rfed `[DISTRO] SENT` to the phone, phone decrypted it.
- Phone as that distro → simulator: direct link through the gateway,
  delivered in under 2 s, simulator shows the distro as the sender.
- APNs: `ApnsTokenRegistrar` throws `badApnsToken` on the simulator (it
  requires a 64-hex token). Simulator only; check on a device.

Testing notes: the app logs with `print()`, which `log show` does not
capture — launch with `xcrun simctl launch --console-pty <udid>
com.newendian.Retichat > file`. iOS autocorrect rewrites typed test text
("ios-to-distro" became "iOS-to-distribute"); use tokens it leaves alone.
A fresh simulator app dials the built-in public backbones — set its
interfaces to the LAN first (the NSE copies the app's config).

## How to verify

- Unit: `cargo test -p lxmf_rust --lib`, `cargo test -p reticulum_rust --lib`
  after the rebuild; the iOS crate `cargo test` if it has tests.
- Staging, never production: `STAGING_PHP=local ./test-harnesses/staging/staging.sh up`
  (without `STAGING_PHP=local` the gateway registers with the production-
  attached selectivesubconscious.com). Wait ~3 minutes after `up` for
  rfed's paced announces. Then in the simulator: hold a distro, a web
  browser A (harness `openNode` with `EXCHANGES.local`) sends to it →
  message arrives on the simulator via distro; the simulator sends as the
  distro → A sees `src = distro`; transfer → A shows "Import Distro
  Identity". The Android equivalents are the `DistroDebugReceiver` ops and
  `probe_phone_holds_distro.mjs`; write the iOS equivalents against the
  simulator tools.
- The first message to a distro whose announce has not been heard yet still
  pays the 5 s direct fallback on every client (router checks only at
  submission). Known, not fixed anywhere.
